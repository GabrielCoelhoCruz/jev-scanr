# Changelog

## Unreleased

Fixes from a cold review of 0.4.0-alpha, plus retrieval and cut changes. No existing question changed, and plans from earlier versions still verify.

- **`jevs baseline --report FILE --out DIR`** compares, offline in one `report.json`, the length ranking of its functions with Jev's ranking on `function_should_split`: both top-N lists (`--top`, default 5), each function's position in the other ordering, the top-N overlap, and the functions without a score, kept as gaps with no P imputed. No API call, no key, nothing is sent, the input is only read, and `--out` must be a new folder. The package now ships `examples/demo-app/expected/report.json`, so the command also runs from an installed package, with the report at `node_modules/jev-scanr/examples/demo-app/expected/report.json`; from a clone: `jevs baseline --report examples/demo-app/expected/report.json --top 5 --out /tmp/demo-baseline` (top-5 overlap 4 of 5 on the recording). With no labels, the output says only where the two orderings agree or differ; it does not measure the quality of either ranking. The labeled-sample comparison stays in `docs/BASELINE.md`.

- **Stored runs read back offline.** `jevs report` and `jevs continue` now read a stored run the way `rescore` does, by binding each stored answer to a request's content (unit and request hash) instead of requiring the plan hash, which covers the scanner version and the root path. The shipped demo run (`examples/demo-app/expected/`) can be reported and continued offline with the plan shipped beside it. `--run-dir` accepts a run folder or the output folder of a `scan --run`, and a journal whose answers belong to other requests is refused naming the mismatch.

- **Per-signal display cuts** (`cuts.json`, `docs/CUTS.md`). `function_should_split` now defaults to cut 0.5 and floor 0.35 (was 0.7 and 0.5), and `name_vs_behavior` to cut 0.5 and floor 0.2; every other signal keeps 0.7 and 0.5. On the constructed-contrast chimeras this moves recall at the cut from 8 of 50 to 19 of 50 with 2 of 50 untouched controls above it; how many extra items a real project gets is not measured, and no labeled real cell exists between 0.5 and 0.67. `--threshold`, `--cut`, `--cut-signal`, `--floor` and `--floor-signal` override as before. `report.json` `thresholds`, `floors` and `bands.edges` now carry the per-signal values. The recorded demo now lists five items (`registerUser` for `function_should_split`, P 0.52, is over 0.5), and its image was redrawn.
- **A second source of clone pairs** (`src/low-overlap.mjs`, `docs/RETRIEVAL.md`). Adds up to 50 pairs per scan (`--low-overlap N`, 0 turns it off) whose token overlap is under 45% but that share outside names, string literals and overall shape, which is what a mechanical rewrite of one function looks like. They go through `clone_same_policy`. Offline, against the 50 rewritten copies of the contrast set planted in slices of their four pinned repositories, all 50 were proposed (worst rank 38 of 50); most pairs it proposes are not copies, and real copies that drifted are untested. `plan.json` records `retrieval.lowOverlap`, `coverage.lowOverlap` and each pair's `retrievalSource`; `queue.md` is unchanged and `report.json` findings gain `retrievalSource` on such pairs.
- **`name_vs_behavior` is an opt-in catalog signal** (`--signals name_vs_behavior`; `--experimental` does not include it). It asks every function by default; `--name-cue` restricts it to functions whose name words are absent from the body, off by default because on a random real sample of 400 functions it skipped 13 of the 16 that two model readers called imprecise or mismatched. Evidence: the constructed contrast (AUC 0.97 on planted renames) and that sample, where Jev put 0 of 400 at 0.7, and the readers' flagged functions sit at P 0.00 to 0.50. No person labeled anything. `jevs signals` lists it.
- **Plans keep verifying.** The catalog hash is now computed over the core catalog plus only the opt-in signals a plan enables, so a plan for the default or experimental signals has the same hash as before (`da964b59…` for the defaults) and older plans, receipts and the recorded demo still verify and rescore. A plan that enables `name_vs_behavior` has its own hash.
- **The secret filter catches more.** A file is skipped as possible secrets when it holds a quoted-key assignment (`"apiKey": "..."`), a Stripe `sk_live_` or `rk_live_` key, a Slack `xoxa-`, `xoxb-`, `xoxp-`, `xoxr-` or `xoxs-` token, a JWT, or a URL with a user and password (`postgres://admin:...@host`). Template URLs built from variables and the placeholder password `pass`, `password`, `secret` or `changeme` do not match. On 27,529 JavaScript and TypeScript files from two real dependency trees it flags 11 more files than before, all of them URL or JWT examples in test files and type comments. It is still a heuristic; `--list-files` and `--exclude` remain the control.
- **`jevs rescore` works on what ships.** The package now includes `examples/demo-app/expected/plan.json` (a portable copy of the demo plan) and `journal.jsonl`, and `jevs demo` ends with the exact rescore command for the folder it uses. `rescore` matches stored answers to requests by content instead of by the plan hash, which covered the scanner version and the absolute root path, so a plan rebuilt by another version or from another folder re-bands a run whose requests are identical. Any other mismatch now reads "This journal was recorded for plan X, but the plan given is Y ..." instead of "WAL plan/mode mismatch". `scripts/regenerate-demo-reports.mjs` also writes `plan.json`; a test keeps it in step with the recording.
- **README, evidence index.** The README leads with why to use it, tied to `clone_same_policy` and the baseline result. The signal table carries one number per signal (the independent test; `jevs signals` still prints the dev run), and the comparison table is down to four rows with short cells. `EVIDENCE.md` and `evals/results/README.md` now index the constructed-contrast and real-sample write-ups. `CONTRIBUTING.md` calls the pre-registration hash what it is (the rule hash `gate --expect-rule-sha` checks, not the file's byte hash) and a test keeps that number in step with the code.
- **`--list-files` splits two lists:** the files asked about, and the files sent only as context (callers, tests that use them, imports). `--include-tests` help now says test files can still be sent as context and that `--exclude` keeps them out.
- **`jevs --help` says what code decides and what Jev decides,** with the real numbers (8 lines, 2:1 size ratio, 45% token overlap, 500 files), and the usage columns line up. A test ties those numbers to the pipeline's constants.
- **`jevs demo` through npx** ends with the matching `npx github:GabrielCoelhoCruz/jev-scanr ...` commands, because `jevs` is not on the PATH there.
- **`scan --run` without `--yes` or `--cap-usd`** refuses before it builds and prints the plan.
- **Signal status is labeled honestly.** `jevs signals` and the README show the three defaults as "default (experimental, alpha)", and `jevs signals` notes that `function_multiple_responsibilities` reached its 8 reviewed items in one repository while the gate asks for two.
- **Documentation tests check structure,** not sentences: links resolve, version pins agree, required sections exist, the figures quoted in the README match the recorded run and `docs/BASELINE.md`, and every `--flag` shown next to `jevs` exists.

## 0.4.0-alpha

Released 2026-09-30.

- **`jevs demo`** replays the recorded run of `examples/demo-app` (the files in `examples/demo-app/expected/`) with no key and no network. It prints a banner that says it is a recording, with the model, date, request count, tokens and calculated cost, then the recorded `queue.md`. The package now ships the three recorded files it reads (`queue.md`, `RECEIPT.json`, `RESULT.json`) and still leaves out the journal and the reports.
- **README opening rewritten.** One sentence names the decision Jev makes, a measured real-run line follows, and the no-key path comes first, with an image of the recorded queue (`docs/images/demo-queue.png`, drawn from the recording by `scripts/render-demo-image.mjs`). A comparison table sets jev-scanr beside ESLint, `jscpd` and asking a general LLM; every jev-scanr cell points to a measured run or `EVIDENCE.md`, and no accuracy comparison is claimed. The README now says "Jev owns the probabilities; your code owns the policy".
- **Three bands instead of a hard cut.** `queue.md` now lists "worth a look" (P at or above the signal's cut, default 0.7), "uncertain, check" (from the floor, default 0.5, up to the cut) and a count of cells below the band, which stay in `report.json` only. The first list keeps its `## N.` item headings; uncertain items are `###` headings after a bold label. The recorded demo's `registerUser` split question (P = 0.52) lands in "uncertain"; `examples/demo-app/expected/{report.json,report.md,queue.md}` were regenerated from the recorded journal with `scripts/regenerate-demo-reports.mjs` (no API call; the journal, receipt and result are untouched). `--floor N` sets the floor at scan or report time. Where the edges come from, and how weak the evidence under them is: `docs/BANDS.md`.
- **`jevs rescore RUN`** re-cuts a finished run folder from its stored answers: `--cut`, `--floor`, `--cut-signal ID=N`, `--floor-signal ID=N`. No API call and no key. It writes `RUN/rescored-<settings>/` (queue.md, report.md, report.json) and refuses to overwrite.
- **`report.json` gained fields, none were renamed:** per cell `floor` and `band`; `findings[].floor` and `.band`; top-level `uncertain`, `floors` and `bands`; per view `floor` and `uncertain`. `report.md` gained "Uncertain band" and "Floor" columns. `reportHash` changes with the content.
- **Free baseline comparison** (`docs/BASELINE.md`, `evals/baseline/`). On 95 labeled cells of the three default signals, Jev's P did not rank better than function length (two function signals) or jscpd-style token coverage (`clone_same_policy`); no pooled difference is statistically clear, and on the validation-gate sample alone function length ranked `function_should_split` better. Labels are an LLM reviewer's. `evals/baseline/analyze.mjs` reruns the numbers from the committed `cells.json` (no source text, no API call); `build-cells.mjs` documents how the cells were joined from stored answers.
- No change to questions, scoring or scan behavior.

## 0.1.1

- `--paths dir1,dir2` scans only the given directories or files. Units and context come only from them. Files outside are counted, not read.
- The dry run prints coverage next to the cost (`read X of Y source files (Z%)`), and names which directories the 500-file cap skipped. `report.md` and `report.json` carry the same coverage, so a partial scan cannot look complete.
- Bounded concurrency: `--concurrency N` (default 8, at most 32) with a token-bucket limiter at 80% of Jev's documented 40 requests and 100K tokens per second. Each in-flight request reserves its worst-case cost before dispatch, the journal stays write-ahead and valid when requests overlap, and any error (a 429 included) stops new dispatch. There are still no automatic retries. A 429's `retry-after` is recorded, not obeyed.
- Requests are split only when Jev's provider budget requires it. The 24,000-byte trim target is unchanged, so requests at or under it are byte-identical to 0.1.0-alpha. A focus above the target but inside a new 64,000-byte hard cap is sent whole instead of being windowed. On the daily-tracker, t3code and oh-my-pi scans, no unit is split any more (0.29%, 0.13% and 0.66% were).
- **The function index no longer stops at 3,000 functions silently.** The cap (nested functions and test functions count) is now 12,000, and when a lower `limits` value or a very large slice still reaches it, the dry run and the report say `NOT INDEXED` and name the directories. A unit-limit overflow is reported as `NOT PACKED`. Scans of large projects under 0.1.0-alpha were affected: units came only from the files indexed before the cap. Re-scan them.
- Plans from 0.1.0-alpha still verify. No signal or question changed.

## 0.1.0-alpha

First public cut, from the author's earlier prototype. Jev-only pipeline; 22 → 8 questions.

- Default catalog: 7 signals (`clone_same_policy`, `function_should_split`, `magic_policy_literal`, `internal_duplication`, `function_multiple_responsibilities`, `unused_local_or_parameter`, `deep_nesting`). `unreachable_code` is experimental and opt-in. The other 14 are retired, listed with their evidence in `signals/retired.md`.
- Unit kinds: functions, line windows of very long functions, and similar pairs. Catch-block, comment-block and sibling units are gone.
- One command: `scan PATH` is a dry run with a request and cost estimate; `--run --yes --cap-usd N` sends. Outputs: `report.json`, `report.md`, `queue.md`.
- Answer validation accepts a chosen option within 0.01 of the maximum (Jev rounds to two decimals) and flags it `near tie`.
- Continuations for stopped runs, with combined accounting.
- One file per question under `signals/`, with fixtures, a live sanity check (`scripts/check-signal.mjs`) and a written gate for going on by default.
- `evals/`: test a signal the way we did. Case sets with label sources, oracle / null / no-answer / induced-error / served-model checks, noise floor next to every rate, P-variance measurement, an LLM-judge protocol with known-negative controls and calibration against human labels, and a pre-registered gate. Results use the layout of Anthropic's eval report builder (vendored, Apache-2.0).
- `examples/demo-app/`: a small synthetic app with seeded problems, plus one real recorded run (`expected/`).
- Removed experimental modes from the prototype that are not part of this tool.
